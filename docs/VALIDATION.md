# Проверки порта — 25 октября 2026

Среда: Ubuntu 26.04.1 x86_64 в WSL2, ядро 6.18.33.2; .NET 8,
Photino.NET 4.0.16 / Photino.Native 4.0.22 / WebKitGTK 4.1.
Проверены минимальные версии символов нативной библиотеки: GLIBC_2.38,
GLIBCXX_3.4.31. Готовый пакет требует Ubuntu 24.04+/Mint 22+/Debian 13+.

Подтверждены:

- Кросс-сборка self-contained Linux x86_64.
- Политики балансировщика, пороги, режимы, cooldown, паузы оптимизации,
  непрерывность счётчиков трафика при смене ядра.
- Реальная локальная VLESS-передача: HTTP 204 проходит с правильными реквизитами;
  доступный TCP-порт с неверными реквизитами и HTTP 200-заглушка не считаются
  рабочим кандидатом. Проверены параллельные цели и отмена.
- Перенесённые сценарии модели Desktop: очередь ручного выбора, жизненный цикл
  подписок, сохранение TUN при переключении, откат конфигурации, подтверждение
  отказов, отбрасывание устаревших событий и отмена во время запуска/восстановления.
  Проверен PNG QR-код с обратным декодированием через zbar.
- Настоящий TUN с tun2socks/Xray в двух network namespace: IPv4/IPv6 исходящие
  TCP, входящие TCP с адреса за пределами локальной подсети, строгий rp_filter,
  новый физический адрес, сохранение прежних маршрутов, очистка после EOF и
  смерти владельца.
- GNOME GSettings: включение прокси, приостановка для TUN, восстановление
  исходных настроек, сохранение независимых изменений пользователя.
- Настоящее окно WebKitGTK под Xvfb: круговой IPC, загрузка состояний и списков,
  11 палитр плюс системная тема, размер 1180×800 без горизонтального переполнения,
  создание автозапуска и единственный экземпляр приложения.

Это не подтверждает работу всех внешних VPN-серверов и аккаунтов ИИ. Полный
прогон на физических Ubuntu GNOME, Mint Cinnamon и Debian, интерактивный запрос
polkit в их пользовательских сеансах и реальный выход/вход в рабочий стол
ещё не выполнены. Поэтому утверждение о «100% проверенной совместимости»
пока было бы неверным.

Особенности платформы: глобальные горячие клавиши Wayland задаются средствами
окружения; для значка в GNOME Shell требуется поддержка AppIndicator.
Компактный режим реализован как переключение того же окна с закреплением
поверх остальных; отдельного второго WPF-окна в Linux нет.

## Исправление 2.14.1

Устранена взаимная блокировка синхронного LinuxCommand.Run на потоке модели:
ожидания подпроцесса и его потоков больше не захватывают SynchronizationContext.
Проверки GNOME-прокси теперь выполняются на том же dispatcher, что и подключение
в приложении, с ограничением ожидания. Добавлен отдельный регрессионный тест
команды /bin/echo на dispatcher.
